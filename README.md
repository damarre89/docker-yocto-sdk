# yocto-sdk Docker image (Raspberry Pi 3B+ / `raspberrypi3-64`)

Portable cross-compilation environment: Ubuntu 24.04 LTS with the Yocto SDK
generated by `bitbake -c populate_sdk` already installed. Build it once, export
it as a `.tar.gz`, and load it on any machine with Docker.
 
| Item | Value |
|------|-------|
| Base image | `ubuntu:24.04` (`linux/amd64`) |
| Yocto release | wrynose (6.0.x), DISTRO `poky` |
| Target machine | `raspberrypi3-64` (Cortex-A53, aarch64) |
| SDK install path | `/opt/sdk` |
| Cross compiler | `aarch64-poky-linux-gcc` |
| Target sysroot | `/opt/sdk/sysroots/cortexa53-nocrypto-poky-linux` |
 
> The SDK installer targets an **x86_64 host** (`SDKMACHINE = "x86_64"`), so the
> image must be `linux/amd64`. On Apple Silicon it runs under emulation (works,
> but much slower).
 
## Repository layout
 
```
docker-yocto-sdk/
├── Dockerfile
├── entrypoint.sh
├── sdk.sh            # the SDK installer (NOT committed, see below)
├── .dockerignore
└── README.md
```
 
`sdk.sh` is large (hundreds of MB) omit inclusion in repo. 
 
## 1. Generate the SDK installer (see yocto repo)
 
From the Yocto build directory of the 3B+ image, using local dirs:
 
```bash
cd ~/projects/yocto
source layers/openembedded-core/oe-init-build-env build
bitbake -c populate_sdk core-image-base
ls build/tmp/deploy/sdk/        # poky-glibc-x86_64-...-toolchain-<version>.sh
```
 
Copy it next to the Dockerfile with a fixed name:
 
```bash
mkdir -p ~/projects/docker-yocto-sdk && cd ~/projects/docker-yocto-sdk
cp ~/projects/yocto/build/tmp/deploy/sdk/poky-glibc-*.sh sdk.sh
```
 
## 2. Files
 
### `entrypoint.sh`
 
The SDK is unusable until its environment script is sourced (it sets `CC`,
`CXX`, `CFLAGS`, `LDFLAGS`, `SDKTARGETSYSROOT`, ...). The entrypoint does it on
every container start, so any command you run already has the toolchain.

### `Dockerfile`
 
```dockerfile
# syntax=docker/dockerfile:1.7
FROM --platform=linux/amd64 ubuntu:24.04
ENV DEBIAN_FRONTEND=noninteractive LANG=C.UTF-8
RUN apt-get update && apt-get install -y --no-install-recommends \
      python3 xz-utils file ca-certificates git make \
 && rm -rf /var/lib/apt/lists/*
RUN --mount=type=bind,source=sdk.sh,target=/tmp/sdk.sh \
    sh /tmp/sdk.sh -y -d /opt/sdk
COPY entrypoint.sh /usr/local/bin/entrypoint.sh
RUN chmod +x /usr/local/bin/entrypoint.sh
WORKDIR /work
ENTRYPOINT ["/usr/local/bin/entrypoint.sh"]
CMD ["bash"]
```
 
Why each part:
 
- `--platform=linux/amd64`: the SDK host tools are x86_64 binaries.
- `python3`, `xz-utils`, `file`: required by the SDK installer; they are not in
  the minimal Ubuntu image. `git`, `make`, `ca-certificates`: convenience.
- `RUN --mount=type=bind`: the installer is read from the build context without
  being stored in an image layer. A `COPY` followed by `rm` would keep the
  installer in an earlier layer and roughly double the image size.
- `-y -d /opt/sdk`: non-interactive install into a fixed path. The SDK
  relocates its internal paths at install time, so **do not move `/opt/sdk`
  afterwards**.
- `entrypoint.sh`: loads the SDK environment for every command.

## 5. Export and import
 
```bash
# export
./export.sh
 
# import on another machine
docker load < yocto-sdk-rpi3-64.tar.gz
docker image ls yocto-sdk
```
 
The archive contains the toolchain and the full target sysroot, so expect
anywhere from one to several GB.
 
## 6. Usage
 
Interactive shell with the current directory mounted:
 
```bash
./load.sh
```
 
- `--user $(id -u):$(id -g)`: files created in the mounted folder belong to
  your user instead of root.
- On Apple Silicon, add `--platform linux/amd64`.
One-shot build:
 
```bash
docker run --rm --user $(id -u):$(id -g) -v "$PWD":/work yocto-sdk:rpi3-64 \
  bash -c 'make'
```
 
### C / C++ with make
 
`CC`, `CXX`, `CFLAGS`, `CXXFLAGS` and `LDFLAGS` are exported by the SDK
environment, so a standard Makefile picks them up. Strip before deploying:
 
```bash
${STRIP} hello
```
 
### CMake
 
The SDK ships a toolchain file (path may differ; locate it first):
 
```bash
find /opt/sdk -name OEToolchainConfig.cmake
cmake -DCMAKE_TOOLCHAIN_FILE=$OECORE_NATIVE_SYSROOT/usr/share/cmake/OEToolchainConfig.cmake ..
```
 
### Go
 
The SDK is not needed for pure-Go programs. Cross-compile with a normal Go
toolchain instead:
 
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o app .      # Pi 3B+ (64-bit)
CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -o app . # Pi 2 (32-bit)
```
 
## 7. Limitations
 
- Tied to **one image build**: if the Yocto image changes (new libraries or
  packages), regenerate the SDK and rebuild this Docker image.
- Only for `raspberrypi3-64`. The Pi 2 needs its own SDK
  (`bitbake -c populate_sdk core-image-base` in its build directory) and image.
- The SDK installer must remain an x86_64 host SDK. For an aarch64 host SDK,
  set `SDKMACHINE = "aarch64"` in `local.conf` and regenerate (this changes the
  image platform to `linux/arm64`).
## 8. Troubleshooting
 
| Symptom | Likely cause / fix |
|---------|--------------------|
| Installer complains about a missing tool | Add it to the `apt-get install` line; the message names the tool. |
| `file t` reports `x86-64` | SDK environment not loaded; check that `/opt/sdk/environment-setup-*` exists and the entrypoint runs. |
| Built files owned by root | Run with `--user $(id -u):$(id -g)`. |
| Very slow builds on a Mac | Apple Silicon runs the image under emulation. Use an x86_64 machine or an aarch64 host SDK. |
| `exec format error` on Apple Silicon | Missing emulation; enable it in Docker Desktop and pass `--platform linux/amd64`. |
| Binary does not run on the Pi | Wrong target: this SDK produces aarch64 (Pi 3B+, 64-bit image) binaries only. |
